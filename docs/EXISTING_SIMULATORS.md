# Existing simulators checked before adding programming

ChipSim's source debugger is an experiment interpreter over its reviewed behavioral models. Native instruction execution should use a suitable backend; there is no shared binary format or ISA for every chip in the reference library.

| Project                                                                                          | Evidence inspected                                                                                                                              | Useful fit and limits                                                                                                                                                                                                            |
| ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Renode](https://github.com/renode/renode)                                                       | [GDB documentation](https://renode.readthedocs.io/en/latest/debugging/gdb.html): CPU stepping, breakpoints, firmware/source debugging           | Reusable firmware backend for supported CPU/platform/peripheral combinations. A supported CPU architecture alone does not establish a supported complete chip. ChipSim has no Renode integration yet.                            |
| [wokwi/rp2040js](https://github.com/wokwi/rp2040js)                                              | Local checkout `a304c7486f329dae64be5f65baf28795d62ceb95`, package 1.4.0, MIT LICENSE, PIO `StateMachine.step()` and instruction implementation | JavaScript RP2040 emulator with explicit PIO state; a promising adapter for native PIO programs. Assembly still needs encoding and source maps, plus pin/FIFO/clock configuration. No source copied or runtime dependency added. |
| [NathanY3G/rp2040-pio-emulator](https://github.com/NathanY3G/rp2040-pio-emulator)                | README instruction support and known limitations; Apache-2.0 license indicated by upstream                                                      | Python PIO testing/debugging reference. Its stated instruction and pin-set limitations must be respected. Not a backend for PRU, XMOS or ESP32.                                                                                  |
| [soundpaint/rp2040pio](https://github.com/soundpaint/rp2040pio)                                  | README single stepping, internal register inspection and waveform generation; GPL-2.0 license indicated by upstream                             | PIO-specific debugger design reference. It is not copied into ChipSim.                                                                                                                                                           |
| [XMOS XTC / xsim](https://www.xmos.com/documentation/XM-014363-PC/pdf/xtc_tools_guide_v15.3.pdf) | Unchanged vendor guide in the xCORE folder                                                                                                      | Vendor route for XMOS executables and debugging. No XTC installation or XE loading is implemented in ChipSim.                                                                                                                    |
| [dwfv](https://github.com/psurply/dwfv)                                                          | Existing optional VCD handoff, documented in `TUI.md`                                                                                           | Views recorded waveforms; it does not compile or execute chip programs.                                                                                                                                                          |

The adapter contract should expose source/PC mapping, step/continue/breakpoints, current registers and logical signals, clock/time units, trace export and explicit supported hardware. A full firmware backend also needs the correct compiler/loader, memory map, peripheral models and debugging symbols. It must not silently turn native binaries into a different experiment language.

Current execution: `.chip` experiments over existing models. Native PIO/PRU assembly, ESP32-C6 RISC-V ELF, XMOS XE and eTPU microcode remain separate unfinished backend work. FlexIO and UDB programming require peripheral configuration/hardware-generation support rather than treating them as standalone CPUs.
